# Afterlight 主题实施规划

日期：2026-10-15

工作分支：`feature/afterlight-theme`

起点：`master`，提交 `fb0cc37`

状态：第一阶段本地预览已完成，等待视觉反馈；实现与检查结果见 `PHASE_ONE.md`。

Afterlight 将成为这个博客可以长期使用、继续生长的独立 Hexo 主题。它需要容纳生活记录、城市经验、诗与音乐、游戏和数学研究，表达作者本人的气质，并延续现有写作与阅读能力。启动包提供方向，真实内容决定最终设计；本规划确定工作重点与阶段结果，保留视觉和交互上的调整空间。

## 设计方向

### 从已有的个人表达出发

现有 `source/img/Yougi.png` 是彩色的「Yougi 杨荻」签名 logo，应作为品牌设计的起点。先测试它在导航、页脚及深浅背景上的实际效果，再决定是否需要尺寸不同的版本或单色版本。色彩、比例和呈现方式通过页面预览讨论，不直接套用原型的 `di.`，也不预先改变签名本身。

《做一首世俗的诗》中对于城市、人群和旁观者视角的表达，《Route Six》的夜色，以及白猫随笔中的日光，提供了网站的情绪范围。全站可以有安静、温暖的阅读底色，同时容纳冷色、夜景与更鲜明的作品页。原型中的猫、咖啡、胶带拼贴只作为可选手法，不成为每页重复出现的固定符号。

照片、游戏截图、诗歌场景图、头像和关于页文字都已存在。优先利用这些素材及其真实语境；精选作品、首页图片和引言暂不定稿。Noema 的介绍与现有素材可保留在相关内容中，首页是否展示另行判断。

### 让阅读和发布自然发生

普通文章不增加字段、不配封面，也应具备完整而舒适的默认版式。首页以简短的个人引入、可选代表作和时间顺序文章列表为起点；首屏高度、精选数量、图文比例与模块顺序保持可调，移动端应能较快到达文章列表。

普通随笔重在中文与中英混排的阅读节奏；数学长文需要适当宽度和局部横向滚动；诗歌及其他定制内容保留独立表达空间。深色模式、清晰焦点和减少动画的支持进入基础设计。具体字体、色值、宽度与装饰细节在真实页面中决定。

## 现有脚本如何整合

整合的目标是让功能成为新主题里协调、可靠的一部分。内容处理与页面交互分别安排归属，避免同时运行两套注入逻辑。

| 现有能力 | 当前入口 | 整合方向 |
| --- | --- | --- |
| 专注阅读与阅读工具 | `scripts/reading-mode.js`，`source/js/reading-mode.js`，对应 CSS | 内置为主题阅读组件。继承专注布局、目录、当前章节定位、键盘操作和会话记忆；保留拖动能力的迁移目标，具体工具外形可重设计 |
| 定理与证明的内容生成 | `scripts/statement-renderer.js`，`math-preview/statement.yaml` 与 `vendor/statement.lua` | 初期继续使用现有站点渲染器及逐篇启用方式，保证旧文生成一致。主题负责呈现；是否进一步抽成独立插件，在跑通后再决定 |
| 数学阅读增强 | `source/js/math-statements.js` 与对应 CSS | 整合证明折叠、命题与证明互链、锚点展开、公式和交换图滚动；将固定浅色样式接入主题配色 |
| AI 使用说明 | `scripts/ai-disclosure.js` 与对应 CSS | 沿用现有 `ai` 字段、等级和说明文字，融入新主题文章信息区；明确唯一渲染入口，避免正文重复插入 |
| 搜索与导航补丁 | 阅读脚本中的 Insight 节点恢复、PJAX 事件；数学脚本中的锚点修复 | 新主题按实际导航方案接替搜索和定位功能；只有不再依赖旧行为且通过回归后，才取消相应补丁 |

目前阅读工具使用 `.column-main`、`article.article`、`#toc` 等 Icarus 结构，数学增强也依赖 `article.article > .content`；直接复制文件并不能保证生效。新主题应提供明确的文章与目录挂载点，逐步去除旧主题结构依赖。部分历史文章自身也含有 `.article .content` 样式，必要时保留兼容容器，优先避免修改正文。

站点 `scripts/` 在切换主题后仍会加载。迁移时需要安排主题判断或配置开关，使 Afterlight 使用新组件、Icarus 继续使用原扩展；旧主题的回退能力应在整合过程中验证，而不是留到最后猜测。

## 技术安排

新主题放在 `themes/afterlight/`，页面采用 Hexo 模板和真实数据生成，配合有作用域的 CSS 与少量浏览器脚本。模板引擎在最小页面验证时选择，不因原型使用何种结构而提前锁定。

初期优先采用普通页面导航，把公式、媒体、评论和浏览器前进后退的可靠性做好。PJAX 是否继续采用，依据实际体验收益决定；旧实现里为 PJAX 修复的问题无需机械照搬。

主题配置集中管理签名、导航、首页介绍、精选内容和阅读选项。首轮精选可通过主题配置引用现有文章，避免为了试设计改动历史 front-matter；需要时再兼容逐篇 `featured` 等字段。摘要使用现有 description、excerpt 或安全的纯文本回退，不能将诗歌样式、AI 声明、公式源码混入首页简介。

数学渲染保留现有文章开关与 Pandoc 路径，统一协调 MathJax 的加载，避免重复初始化或漏掉旧文章。搜索、Giscus、图片放大和音频作为现有能力接续；字体和装饰资源尽量不增加必需的外部依赖。RSS、站点地图等扩展在发布准备时核对，不把它们假定为已经具备的功能。

本地预览采用单独的主题覆盖配置、构建缓存和输出位置，保留 `_config.yml` 中的正式主题选择。开发分支隔离 Git 历史，但缓存、依赖和生成目录仍在同一工作目录中，预览也应安排隔离。

## 分阶段推进

### 第一阶段 建立有真实内容的设计样本

完成最小主题骨架与本地预览，先做首页和普通文章页。使用现有签名、真实标题与一篇普通 Markdown 长文，比较无封面、有图精选以及手机上的效果。同步用 Route Six 和数学文章试装页面容器，尽早发现结构冲突。

阶段结果是一组可以实际浏览、能讨论整体气质的页面。此时决定主要字体、阅读宽度、首页密度和品牌呈现方式；装饰细节与最终文案继续留白。

### 第二阶段 接通内容与阅读能力

完成归档、分类、标签、分页、关于页、上下篇导航及完整深浅模式，接入阅读工具、目录、数学增强和 AI 说明。保留特殊作品的原有内容与媒体，验证普通 Markdown、定制 HTML、marked 数学和 Pandoc 数学都能顺畅阅读。

搜索、评论、图库在这一阶段明确实现路径并接入；若某项需要延期，在预览中清楚说明。阶段结果是可以连续浏览全站的主题，功能缺口有明确清单。

### 第三阶段 根据作品打磨视觉与交互

围绕签名、真实照片和作品气质调整首页及阅读页。重点处理 Route Six 的夜景与外层页面关系、白猫随笔的图文节奏、长数学文章的宽度、深色下的自定义内容，以及手机目录与阅读工具的操作。

每轮集中调整少数影响体验的问题，通过桌面和手机对照做取舍。个别作品的专属布局、更丰富的动效、额外首页模块都可以在这里决定是否值得加入。

### 第四阶段 验收与发布准备

完成真实构建、资源与链接检查、移动端与键盘回归、搜索和评论加载核验，以及切回 Icarus 的验证。补齐配置说明、已知限制和切换步骤，再决定上线时机。生产配置切换、合并或推送主分支及部署另行安排。

## 保留到预览时决定的事项

- 签名使用完整彩色版本，还是按导航和页脚分别设计呈现方式。
- 首页更偏简洁文字与作品精选，还是增加一块由真实照片构成的视觉区域。
- 暖纸色与城市夜色各自占多少比重，深色模式如何形成自己的层次。
- 精选作品选择、首页引言、导航名称，以及是否单设诗与音乐入口；旧分类层级保持兼容。
- 阅读工具保留哪些入口、默认目录如何出现，拖动交互如何与新页面协调。

这些事项不阻碍最小主题骨架与内容兼容工作，不需要现在逐一拍板。先用现有材料做出可比较的结果，再集中讨论。
